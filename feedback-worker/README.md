# PULSE Feedback — настройка

Форма в тестовой версии уже добавлена, но **отправка не работает до подключения серверного обработчика**.

## Обработчик
Разверните `feedback-worker/index.js` как Cloudflare Worker. В настройках Worker → Settings → Variables and Secrets добавьте секреты:
- `GITHUB_TOKEN` — fine-grained GitHub PAT с разрешением Contents: Read and write **только** для репозитория `vv79sk6r8j-cpu/pulse`.
- `TELEGRAM_BOT_TOKEN` — новый токен Telegram-бота, не публикуйте его.
- `TELEGRAM_CHAT_ID` — числовой идентификатор личного чата с ботом (сначала отправьте боту `/start`; ID можно получить через Telegram Bot API `getUpdates` в защищённом окружении).

Обработчик сохраняет заголовок и описание в `Feedback/<дата>-<id>.md` в публичной ветке `main`, **не сохраняет контактные данные в GitHub**, и посылает Telegram-уведомление с контактами. Не просите пользователей указывать персональные данные пациентов.

## Подключение к сайту
В GitHub Actions workflow для шага сборки preview передайте `VITE_FEEDBACK_ENDPOINT` равным HTTPS-адресу Worker. Не используйте для этой переменной секрет: URL публичный. Токены никогда не должны попадать в переменные Vite или браузерный код.

## До публикации
- Проверить Worker и запись в GitHub, доставку в Telegram и отказ при ошибках.
- Добавить антиспам-защиту (например Cloudflare Turnstile и серверную проверку токена) и ограничение частоты запросов перед публичным включением формы.
- Учитывать, что GitHub-репозиторий публичный и содержание обращений может быть доступно всем.
- Обработчик сейчас принимает запросы с origin GitHub Pages, но CORS не является антиспам-защитой.
