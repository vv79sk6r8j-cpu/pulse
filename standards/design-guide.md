Статус: черновик v0.1 для PULSE 0.4. Основа — текущие src/styles.css и src/App.tsx. Новые нормы ниже являются целевыми, а не утверждением о полном соответствии существующего интерфейса.

## 1. Принципы
Клиническая читаемость, единообразие, минимум декора, предсказуемая навигация. Не использовать цвет как единственный носитель клинического смысла. Интерфейс на русском языке; общепринятые медицинские сокращения допустимы.

## 2. Цвет и типографика
Текущая тёмная палитра: фон #091A25, sidebar #0E2734, карточки #102E3C, границы #284D5B, основной текст #EDF7F9, вторичный #9BB6C0, акцент #71DED1. Не вводить новые оттенки без смысловой роли; постепенно вынести цвета в CSS custom properties. Светлая тема — будущая отдельная палитра, не инверсия.
Inter, system-ui, -apple-system, Segoe UI, sans-serif. Текущие заголовки страниц 27–37 px, заголовки секций 23 px, карточки 16 px, основной текст статей 14 px. Целевая норма для длинного чтения 16 px, межстрочный интервал 1.5–1.7. Числовые результаты — tabular-nums, единицы измерения рядом. Контраст WCAG AA: обычный текст 4.5:1, крупный 3:1, значимые контуры и состояния 3:1.

## 3. Графемы
Lucide React — базовый набор. Собственные SVG только при отсутствии подходящего символа. Единый эталон viewBox 0 0 24 24, stroke 2, fill none, stroke=currentColor, round cap/join. Допустим иной viewBox при пропорциональной толщине: например 64×64 соответствует 5.33 единицы при 2/24; для сложного POCUS текущие 4.5/64 являются оптическим исключением, подлежащим проверке на стенде. Не смешивать заливку и контур без причины. Без теней, градиентов, текста внутри графем. Оставлять поля, избегать обрезки штрихов и наложений. Проверять узнаваемость в 19, 21, 23 и 24 px (текущие размеры навигации и карточек), одинаковый визуальный вес, контраст, состояния hover/active/disabled. Иконки с подписью декоративны (aria-hidden); кнопки без текста имеют aria-label. POCUS — утверждённая форма датчика с отделёнными волнами; не заменять абстрактным пульсом. Логотип — отдельное исключение, сохранять пропорции и фирменные цвета.
Целевая структура: src/components/icons/index.ts (единый экспорт Lucide и собственных компонентов), отдельные *.tsx для собственных графем. Не дублировать SVG по страницам.

## 4. Линии, формы, компоненты
Целевой шаг отступов 4 px; типовые 8/12/16/20/24/32. Границы карточек и полей 1 px, фокус 2 px с отступом 3 px, смысловые акцентные линии 2–3 px. Радиусы полей 10–12 px, карточек 15–20 px, статусов pill. Использовать существующие компоненты, не вводить локальные стили без необходимости. Состояния: default, hover, focus-visible, active, disabled, loading, error, success, empty. Ошибки обязательных полей — контур и текст; клиническое предупреждение отличается от ошибки ввода. Поле числа и выбор единицы в одной строке; не скрывать единицы и интерпретацию. Не полагаться на hover на телефоне. Целевая зона касания 44×44 CSS px.

## 5. Адаптивность
Текущие точки 950, 760, 390 px; мобильная навигация и safe-area сохраняются. Проверять 320, 390, 430, 768, 1024, 1440 px, iOS Safari и Android Chrome, клавиатуру, увеличение 200%, reduced motion. Не допускать горизонтального скролла страницы; таблицы могут прокручиваться в собственном контейнере. Не перекрывать контент фиксированной навигацией.

## 6. Визуальные материалы и хранение
Целевая структура для текущего Vite:
- src/components/icons/ — программные UI-графемы.
- public/assets/brand/ — логотипы, wordmark, фирменные изображения.
- public/assets/ui/ — статические изображения интерфейса.
- public/assets/content/theory/ — иллюстрации статей.
- public/assets/content/pocus/ — схемы и изображения POCUS.
- public/assets/content/references/ — справочные иллюстрации.
- public/assets/content/documents/ — изображения для материалов (PDF и исходные документы остаются в своей документной системе).
- public/assets/banners/ — баннеры и промоматериалы.
- docs/visual-assets.md — реестр и правила миграции.

Имена файлов: lowercase kebab-case, стабильный идентификатор, без пробелов, персональных данных и абсолютных локальных путей. SVG для векторных схем, WebP для фото, PNG при необходимости lossless/прозрачности. Сохранять оригинал отдельно от оптимизированных производных при наличии прав. Для Vite использовать BASE_URL при обращении к public, чтобы preview и production работали под разными префиксами. Не использовать произвольные внешние hotlinks.
В реестре: ID, назначение, путь, alt, подпись, автор, источник, лицензия, дата, статус проверки, версия. Для клинических изображений — проверка содержания и отсутствие идентифицирующих данных пациентов. Не считать небольшую переработку чужой графики гарантией лицензии.

## 7. Будущая админка Django/Wagtail
Разделить системные статические ресурсы (static) и редактируемые материалы (media). Логотипы и системные графемы по умолчанию остаются версионируемыми ресурсами приложения; управляемые варианты бренда — через настройки сайта с безопасным fallback. Иллюстрации и баннеры — через Wagtail Images, коллекции по назначению, ImageChooserBlock/ссылки на записи изображений вместо жёстких URL. Alt и подпись учитывать в контексте размещения; лицензия и источник — метаданные. Использовать renditions для размеров, права доступа, валидацию типа/размера, безопасную обработку SVG, резервное копирование media. Не хранить пользовательские загрузки в Git. При миграции сохранить соответствие стабильных ID и новых записей CMS.

## 8. Приёмка
Перед merge: сборка, тесты, визуальная проверка ПК/мобильных, контраст, доступность, отсутствие обрезки иконок, корректные пути на preview и production, проверка источников изображений. Изменения стандарта фиксировать в истории Git. Текущие несоответствия исправлять отдельными проверяемыми задачами, не массовой заменой без тестов.
